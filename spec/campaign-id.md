# キャンペーン番号 `RSJP-C` の仕様（草案 0.1）

## 1. 目的

RustSec の助言は crate ごとに 1 件ずつ出ます。1 つの攻撃が複数の crate にまたがるとき、それらが同じ事件だと示す番号はありません。
`RSJP-C` は、**既存の助言を事件のまとまりで束ねるための番号**です。個々の助言の代わりにはなりません。

## 2. 形式

```
RSJP-C-YYYY-NNN
```

| 部分 | 意味 |
|---|---|
| `RSJP` | 発行者（RustSecJP） |
| `C` | Campaign（一連の攻撃のまとまり） |
| `YYYY` | 最初の悪性版が公開された年（UTC） |
| `NNN` | その年の通し番号。3 桁、001 から。足りなくなれば桁を増やす |

通し番号は、その年の中で **発生した順** ではなく **発行した順** に振ります（後から古い事件を足しても、既存の番号を動かさないため）。

## 3. 番号を振る対象

次のどちらかに当てはまるものに振ります。

- 2 つ以上の crate にまたがる攻撃
- 1 つの crate だけでも、手口として記録する価値があるもの（正規の crate の乗っ取り、公開アカウントの侵害など）

1 つの crate だけの単純な名前の偽装は、原則として対象にしません。RustSec の助言で足ります。

## 4. 記録に書くこと

各キャンペーンは `campaigns/RSJP-C-YYYY-NNN/` に置きます。

| ファイル | 中身 |
|---|---|
| `campaign.toml` | 機械で読める記録（下の項目） |
| `README.md` | 人が読む解説記事 |
| `iocs.csv` | 痕跡情報（ハッシュ、無害化した通信先など） |

`campaign.toml` の項目:

- **id / title / summary**: 番号、題名、3 行ほどの要約
- **status**: `draft`（草案）/ `published`（公開）/ `merged`（統合済み）/ `withdrawn`（取り下げ）
- **dates**: 最初の悪性版の公開、発見、削除の時刻（UTC）
- **members**: 関係する crate と版、対応する既存の番号（RUSTSEC / GHSA / MAL / CVE）、役割（乗っ取られた crate、偽装 crate、ペイロードの運び役 など）
- **links**: 束ねた根拠。1 件ごとに、種類（同じ公開アカウント、同じ通信先、同じコード など）、**自分で確認したか他者の報告に拠るか**、確信度（高・中・低）、出典
- **score**: RSJP Score の点数と内訳の文字列（[severity-score.md](severity-score.md)）
- **related**: 関連するほかのキャンペーン番号
- **history**: 更新の履歴

ひな形は [`campaigns/_template/campaign.toml`](../campaigns/_template/campaign.toml) にあります。

## 5. 束ねる根拠の決まり

- 根拠が 1 件も無いものは束ねません。「時期が近い」「手口が似ている」だけでは束ねません。
- 確信度「高」は、自分たちで確認できた根拠があるときだけ付けます。
- 攻撃者の名指しはしません。帰属は出典つきの引用にとどめます。

## 6. 番号の寿命

- 一度発行した番号は消しません。使い回しもしません。
- 後から 2 つのキャンペーンが同じものだと分かった場合は、片方を `merged` にして、統合先の番号を書きます。
- 誤りだった場合は `withdrawn` にして、理由を書きます。
- 中身を変えたら `history` に日付と内容を残します。

## 7. ほかの番号との関係

- `RUSTSEC-` の助言 ID は発行しません。`RSJP-C` は RustSec の助言を **参照する** だけです。
- 新しい悪性 crate を見つけた場合は、先に crates.io へ報告します。`RSJP-C` の公開は、削除と RustSec の助言が出た後にします。
