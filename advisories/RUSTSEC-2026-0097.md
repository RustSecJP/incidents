# RUSTSEC-2026-0097: `rand` が、独自のロガーから `rand::rng()` を使うと unsound になる

| | |
|---|---|
| crate | [`rand`](https://crates.io/crates/rand) |
| 種類 | unsound（安全なコードから未定義動作を起こせる） |
| 助言の日付 | 2026-04-09 |
| 影響を受ける版 | 0.7.0 以上で、直った版より前のもの |
| 直った版 | `0.8.6` 以上の 0.8 系、`0.9.3` 以上の 0.9 系、`0.10.1` 以上（0.7 系には無い） |
| 影響を受けない版 | 0.7.0 より前 |
| 別の番号 | GHSA-cq8v-f236-94qc |
| 原文 | [RUSTSEC-2026-0097](https://rustsec.org/advisories/RUSTSEC-2026-0097.html)（CC0-1.0） |

## 要約

`rand` の `ThreadRng` を、**独自に実装したロガーの中から**使うと、可変参照が二重にでき、未定義動作になります。起きるのは、下の「原文の訳」にある条件が**すべて**そろったときだけです。ふつうに `rand::rng()` や `rand::thread_rng()` を使っているだけなら、当たりません。

ただし `rand` は非常に多くの crate が依存しているので、直った版に上げておくのが安全です。

## 自分が影響を受けたかの確かめ方

`Cargo.lock` に入っている `rand` の版を見ます。

```shell
cargo tree -i rand --depth 0
```

表示された版が「直った版」より前で、かつ独自のロガー（`log::Log` の実装）の中で乱数を使っている場合は、影響を受ける可能性があります。

## 直し方

同じ系列の中で、直った版に上げます。

```shell
cargo update -p rand
```

0.8 系なら 0.8.6 以上、0.9 系なら 0.9.3 以上、0.10 系なら 0.10.1 以上になっていることを、もう一度 `cargo tree -i rand --depth 0` で確かめます。

**0.7 系には直った版がありません。** 0.7 系を使っている場合は、`Cargo.toml` で 0.8.6 以上に上げる必要があります。0.7 系と 0.8 系では API が一部違うので、コードの手直しが要ることがあります。

すぐに上げられない場合は、独自のロガーの中で `ThreadRng` を使わないようにします。

## 原文の訳

報告（[@lopopolo](https://github.com/lopopolo) による）によると、次の条件が**すべて**そろったとき、`rand` ライブラリは [unsound](https://rust-lang.github.io/unsafe-code-guidelines/glossary.html#soundness-of-code--of-a-library) になります（つまり、公開 API を使う安全なコードから未定義動作を起こせます）。

- `log` と `thread_rng` の機能（feature）が有効になっている
- [独自のロガー](https://docs.rs/log/latest/log/#implementing-a-logger)を定義している
- その独自のロガーが `rand::rng()`（以前の `rand::thread_rng()`）を取り、`ThreadRng` の `TryRng`（以前の `RngCore`）のメソッドを呼ぶ
- 独自のロガーから呼ばれている最中に、`ThreadRng` が種の入れ替え（reseed）をする（またはしようとする）。これは、乱数を 64 kB 生成するごとに起きる
- trace レベルのログが有効になっている。または warn レベルのログが有効で、かつ乱数の元（`getrandom` crate）が新しい種を返せない

`ThreadRng` の `TryRng`（以前の `RngCore`）のメソッドは、`unsafe` のコードで `*mut BlockRng<ReseedingCore>` を `&mut BlockRng<ReseedingCore>` に変換しています。上の条件がすべてそろうと、同じものを指す可変参照が 2 つでき、Stacked Borrows の規則に違反します。Miri は、例のコードでこの違反を検出できます。[同じものを指す可変参照を作ることは未定義動作](https://doc.rust-lang.org/stable/nomicon/references.html)なので、最適化したビルドでどう動くかは予測しにくくなります。
