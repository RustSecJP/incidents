# RUSTSEC-2026-0384: Tokio v1.54.0 の `tokio::time::Interval` に競合状態がある

| | |
|---|---|
| crate | [`tokio`](https://crates.io/crates/tokio) |
| 種類 | メモリ破壊、スレッド安全性（競合状態、解放済みメモリの使用） |
| 助言の日付 | 2026-10-21 |
| 影響を受ける版 | `1.54.0` だけ |
| 直った版 | `1.54.1` 以上 |
| 別の番号 | CVE-2026-115567、GHSA-5wjr-9356-4wc8 |
| 原文 | [RUSTSEC-2026-0384](https://rustsec.org/advisories/RUSTSEC-2026-0384.html)（CC0-1.0） |

## 要約

Tokio **1.54.0 だけ**の問題です。マルチスレッドのランタイムで `tokio::time::Interval` を使うと、内部のタイマーが競合し、解放済みのメモリを使うことがあります。安全な Rust のコードだけで起き、クラッシュやヒープの破壊につながります。

`Sleep` と `Timeout` は影響を受けません。1.54.0 は yank 済みです。

## 自分が影響を受けたかの確かめ方

```shell
cargo tree -i tokio --depth 0
```

`1.54.0` と表示されたら影響を受けます。それ以外の版なら当たりません。

## 直し方

```shell
cargo update -p tokio
```

1.54.1 以上になったことを確かめます。1.54.0 は yank されているので、`Cargo.lock` を作り直せば選ばれなくなります。ただし、すでに `Cargo.lock` に書かれている場合は、上のコマンドで明示して上げる必要があります。

## 原文の訳

### 概要

マルチスレッドのランタイムで、`Interval::poll_tick` とランタイムのタイマー処理（time driver）の間に競合状態があります。

影響を受けるのは `Interval` だけです。`Sleep` と `Timeout` は影響を**受けません**。

### 詳細

Tokio v1.54.0 では、`tokio::time::Interval::poll_tick`（`.tick().await` を含む）とランタイムのタイマー処理の間で競合が起きます。このとき、内部のタイマーの項目が、それを発火させているタイマー処理のスレッドと同期しないまま捨てられることがあります。その結果、タイマーの waker とタスクの状態について、安全な Rust の中でデータ競合と解放済みメモリの使用が起き、assert によるパニック、タスクの参照カウントの破壊、ヒープのメモリの破壊につながります。

このバグは https://github.com/tokio-rs/tokio/pull/8458 で入り、https://github.com/tokio-rs/tokio/pull/8692 で直りました。

### 影響

マルチスレッドのランタイムで `Interval` を使うアプリケーションで、クラッシュや解放済みメモリの使用が起きることがあります。

本番のシステムでクラッシュにつながることが分かっているため、Tokio の v1.54.0 は yank されました。

### 謝辞

セキュリティポリシーの手順に沿って非公開で報告してくれた [creepycode](https://github.com/ByteZ1337) と [carabistouille](https://github.com/carabistouflette) に感謝します。2 人は、それぞれ別々にこの問題を報告しました。
