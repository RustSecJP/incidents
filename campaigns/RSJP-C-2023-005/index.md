## 要約

crates.io の利用者 `gabielle55131` が、Tauri の Windows 通知 crate（`tauri-winrt-notification`）に名前を似せた crate を 2 つ公開しました。RustSec の助言によると、これらは「Windows のホストで任意のマルウェアのペイロードを動かすための、名前の偽装のまとまり」でした。crate は削除され、利用者は使えなくされています。

この事件は 2023 年 11 月に処理されましたが、当時は公に知らされなかったようです。RustSec の助言が追加されたのは、約 2 年 4 か月後の 2026-03-26 です。当時の削除に関わった担当者が、手元のメモから過去の削除をまとめて登録したものです。そのため、**版、ダウンロード数、公開日、ペイロードの中身は、どれも記録が残っていないか、公開されていません。**

RustSec の助言は crate ごとに 1 件ずつ、計 2 件出ています。この記録では、同じ利用者が公開したことを根拠に、それらを 1 つのキャンペーンとして束ねます。

## 自分が影響を受けたかの確かめ方

次のどれかに当てはまる場合は、影響を受けた可能性があります。

- `Cargo.lock` に、`tauri-win-rt-notification`、`tauri-winrt-notifications` のいずれかがある。
- `~/.cargo/registry/cache` に、これらの名前の `.crate` ファイルが残っている。

```shell
# プロジェクトのロックファイルを調べる
grep -nE 'name = "(tauri-win-rt-notification|tauri-winrt-notifications)"' Cargo.lock

# 手元のキャッシュを調べる
ls ~/.cargo/registry/cache/*/ 2>/dev/null | grep -E '^(tauri-win-rt-notification|tauri-winrt-notifications)-'
```

助言には「版の情報もダウンロードの記録も、もう残っていない」とあります。どの版が悪性だったかは分からないので、**これらの名前の crate はどの版でも悪性とみなしてください。** これらの名前は、いまは crates.io にありません。

名前を似せた先と思われる本物の crate（`tauri-winrt-notification`）は、この事件の対象ではありません。

見つかった場合は、その crate をビルドしたり動かしたりした Windows の環境を、マルウェアに感染した可能性があるものとして扱ってください。ペイロードが何をするのかは公表されていないため、その環境にあった認証情報も入れ替えるのが安全です。

## 手口

この節は、RustSec の助言の短い記述だけによります。検知した企業の解析は、見つかりませんでした。RustSecJP は検体を入手しておらず、自分では確認していません。

- **名前の偽装**: 助言は「名前の偽装（typosquatting）のまとまり」としています。名前を見ると、本物に似た名前に `-rs`、`-main`、`-win` などを足したり、区切りや単数・複数を変えたりしたものです（ここは自分の推測です）。
- **対象の OS**: 助言は「Windows のホストで任意のマルウェアのペイロードを動かす」としています。
- **分かっていないこと**: ペイロードがインストール時（`build.rs`）に動くのか、ライブラリを使ったときに動くのか、どこから何を取ってくるのか、何を盗むのかは、公表されていません。

なお、助言を登録した PR の本文には「深く調べ直してはいない。メモに具体的な動きが無ければ、おおまかな説明を書いた」とあります。上の「Windows で任意のマルウェアを動かす」という記述も、おおまかな説明である可能性があります。

### 束ねなかったもの

同じ PR #2747 では、ほかの利用者が公開した crate についても、同じ文面の助言が登録されています。`Kraded`（12 個、助言の日付 2023-11-15）、`TerryDavisSoldier`（3 つ、助言の日付 2023-11-18）、そして 1 つだけの `bit-flags`（利用者 `alexrichton`、2023-12-22）です。

`Kraded`、`TerryDavisSoldier`、`gabielle55131` の助言の日付は 2023-11-15〜11-20 に集まり、手口の記述も同じです。しかし、文面は担当者がメモからまとめて書いたもので、同じペイロード、同じ通信先、同じコードであるとはどこにも書かれていません。「時期が近い」「手口が似ている」だけでは束ねない決まりなので、利用者ごとに別の記録にしています（[`RSJP-C-2023-003`](https://github.com/RustSecJP/incidents/blob/main/campaigns/RSJP-C-2023-003/index.md)、[`RSJP-C-2023-004`](https://github.com/RustSecJP/incidents/blob/main/campaigns/RSJP-C-2023-004/index.md)）。`bit-flags` は 1 つだけの名前の偽装なので、記録を作っていません。

## 対策

- **crate の名前を確かめる**: `-rs`、`-main`、`-win` などを足した名前は、本物の別名とは限りません。crates.io のページで、リポジトリの URL が実在するか、ダウンロード数と公開日が不自然でないかを見ます。
- **公開されたばかりの crate をすぐに使わない**: 新しい依存を足すときは、公開からの日数と、公開した利用者の他の crate を見ます。
- **助言データベースだけに頼らない**: この事件は、削除から助言の登録まで 2 年以上かかりました。過去には、公に知らされずに削除された悪性の crate もあります。
- **Windows でのビルドに注意する**: `build.rs` や手続きマクロは、ビルドするだけで動きます。知らない crate は、使い捨ての環境で試します。

## 分かっていないこと

- **公開日、版、ダウンロード数**。助言に「もう残っていない」とあります。
- **助言の日付の意味**。2023-11-20 が削除の日か、通報の日か、別の日かは書かれていません。
- **ペイロードの中身**。動く時点、通信先、盗むものは公表されていません。助言の記述そのものが、メモからのおおまかな説明である可能性があります。
- **削除の仕方**。助言の本文は「yank された」としています。2026-11-20 には 2 つとも crates.io の索引から消えているので、どこかの時点で完全に削除されたと思われますが、その日は分かりません。
- **ほかの利用者のまとまりとの関係**。`Kraded`（12 個、助言の日付 2023-11-15）、`TerryDavisSoldier`（3 つ、助言の日付 2023-11-18） の crate も、同じ時期に同じ文面で登録されています。同じ攻撃者によるものかは、公表された根拠がありません。
- **見つけた人と経緯**。誰が、いつ通報したかは公表されていません。
- **検知した企業の解析**。2023 年 11 月〜12 月の企業の記事、crates.io チームや Rust のブログの記事は、見つかりませんでした。脆弱性データベース（Snyk など）の項目はありますが、RustSec の助言の文面を言い換えたもので、独自の解析ではないようです。
